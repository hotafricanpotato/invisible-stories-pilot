# Подготовка GitHub Pages (без публикации)

База: story-design-system, 37444f2a69b4e6f6e480aef566ad45928f630573.

## Режимы

- `npm run build`: прежний BrowserRouter, base `/`, результат `frontend/dist/`.
- `npm run build:pages`: HashRouter, base `/invisible-stories-pilot/`, результат `frontend/dist-pages/`.
- Vercel не должен использовать команду build:pages. Его vercel.json не изменён.
- Адрес Pages: `https://hotafricanpotato.github.io/invisible-stories-pilot/#/statistics/2` (аналогично другим маршрутам).
- URL без `#`, например `/invisible-stories-pilot/statistics/2`, на обычном статическом сервере возвращает 404. Это ожидаемо; распространять нужно hash-ссылки.

Сценарии, оформление, изображения, модель прогресса и ключ localStorage не меняются. Пути картинок получают BASE_URL только в компонентах отображения. Внешние URL не изменяются. Клавиатурная ссылка «К содержанию» фокусирует main, не заменяя hash-маршрут.

## Проверки локально

Из frontend:

```sh
npm ci
npm test
npm run test:content
npm run build
npm run build:pages
npm run test:e2e:pages
npm run test:e2e
```

Для Pages-тестов нужен Chromium: по умолчанию /usr/bin/chromium, либо CHROMIUM_PATH. В CI используется установленный Playwright Chromium (`PLAYWRIGHT_BUNDLED_CHROMIUM=1`).

Новый браузерный набор поднимает обычный HTTP-сервер: только реальные файлы dist-pages под /invisible-stories-pilot/, без fallback. Проверяет 404 для неверной формы ссылки, защиту этапов, прямые hash-ссылки и обновление, иллюстрации, клавиатурный переход к содержимому, отсутствие переполнения, localStorage, закрытие и открытие вкладки, reset и историю браузера.

## Workflow — сейчас только подготовлен

`.github/workflows/pages.yml` НЕ содержит push/pull_request/schedule/workflow_run. Только workflow_dispatch с обязательным значением DEPLOY_PAGES и проверкой ref=refs/heads/story-design-system. Обычный push не запускает его. Deploy зависит от успешных сборок и тестов; используется GITHUB_TOKEN, отдельный PAT не требуется.

Workflow находится в корневой .github/workflows/, команды выполняются в frontend. Артефакт содержит только dist-pages, а не репозиторий/сценарные DOCX. Окружение github-pages и минимальные разрешения pages:write/id-token:write используются только для deploy.

## Первое включение — только после отдельного разрешения

1. Согласовать commit/push подготовленных файлов в story-design-system. Это само по себе не публикует сайт.
2. Проверить, нет ли уже Pages-сайта данного репозитория, и текущую default branch. Ни то ни другое автоматически не меняется.
3. Отдельно разрешить настройку Settings → Pages → GitHub Actions. Разрешить окружению github-pages развёртывание из story-design-system; не менять Vercel, DNS и main.
4. Важное ограничение GitHub: для первоначального workflow_dispatch файл workflow должен существовать в default branch. Если это main и файла там нет, текущий ручной workflow не появится как запускаемый. Не менять main/default branch ради обхода без согласования.
5. В таком случае отдельно согласовать способ первого запуска без main: например, последующее добавление ограниченного tag-триггера для специально утверждённой публикации, с проверкой, что тег указывает на согласованный коммит story-design-system. Сейчас такого триггера нет. Нельзя обещать первый ручной запуск текущего файла, пока не выполнено требование default branch.
6. После явно разрешённого развёртывания проверить реальный адрес на компьютере и смартфоне, Wi-Fi/мобильной сети, прямые hash-ссылки, закрытые этапы и полный маршрут. Только затем сравнивать доступность с Vercel.

## Сохранения и платформы

Vercel и github.io имеют разные origin: прогресс не переносится автоматически. Старые сохранения Vercel остаются на Vercel. HashRouter не меняет внутренний формат cursor или правила доступа. Другие проекты одного github.io-origin разделяют localStorage; не использовать тот же ключ в посторонних проектах.

На Pages vercel.json не исполняется, включая его заголовки. HTML/CSS/JS не дают серверной защиты доступа: существующие ограничения выставки — клиентские правила прохождения, как и на Vercel.

Никаких commit/push/merge, настроек Pages и публикации в рамках подготовки не выполнять.
