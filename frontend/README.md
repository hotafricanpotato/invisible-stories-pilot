# «Невидимые истории» — React-пилот

React + JavaScript + Vite. Исходная Streamlit-версия в родительской папке сохранена без изменений. Этот этап не выполняет push или публикацию.

## Запуск

Node.js 24 (см. `.nvmrc`), npm:

```bash
cd frontend
npm ci
npm run dev
```

Production:

```bash
npm run build
npm run preview
```

## Маршрут

Главная → выбор историй → Лиза → выбор → Никита → выбор → 4 экрана статистики → завершение пилота. Карточка Ильи видна, но история ещё в разработке. После каждой истории пользователь возвращается к выбору.

Материалы можно открывать в любом порядке. Для продолжения нужны все три. В карте нужны три ответа и действие «Раскрыть связи». После раскрытия ответы карты не редактируются. Входной тест исключён из интерфейса; его данные оставлены только для совместимости.

URL защищены проверками обязательных шагов. Назад можно вернуться кнопками приложения и браузера. Открытые этапы остаются доступными. Кнопка «Начать заново» с подтверждением полностью сбрасывает ответы и прогресс, возвращает на главную, затем к выбору с доступной Лизой.

## Данные и приватность

Содержание находится в `src/content/`: исходные вопросы и история перенесены в JSON без редакторских изменений. Изображения в `public/assets/nikita/` побайтово идентичны исходным.

Прогресс записывается в `sessionStorage` текущей вкладки (`invisible-stories:pilot:v1`). Перезагрузка его сохраняет; закрытие вкладки обычно завершает сеанс. Браузер может восстановить вкладку вместе с состоянием; для явного удаления используйте «Начать заново». При недоступном хранилище приложение работает в памяти с уведомлением. Восстановленные данные проверяются; несовместимая версия возвращает начальное состояние.

Backend, аналитика, внешние шрифты и отправка ответов отсутствуют. При переходе по первоисточнику открывается внешний сайт; ответы ему не передаются. Ключи правильных ответов присутствуют в статическом пакете, как и любые клиентские данные; это образовательная выставка, не защищённый экзамен.

## Структура

- `src/content/` — утверждённые данные, источники и конфигурация пилота.
- `src/state/` — reducer, восстановление, ограничения переходов, Context.
- `src/components/` — сцены, монологи, переписки, материалы и элементы управления.
- `src/pages/` — маршрут выставки и статистические экраны.
- `src/styles.css` — палитра, коллажи и адаптивная вёрстка.
- `tests/` — сравнение содержания, логика состояния, браузерное прохождение.

`exhibitionConfig.js` задаёт подключённые истории, порядок и отдельные условия открытия статистики для пилота и полной версии. Сейчас статистика открывается после Лизы и Никиты; в полной версии — после всех трёх. Итоговый тест после статистики и эпилог ещё не реализованы. Новые сценарии добавляются только после утверждения.

## Проверки

```bash
npm test
npm run test:content
npm run build
npm run test:e2e
```

Сравнение содержания требует Python 3, но не требует Streamlit. Браузерные тесты используют production-папку `dist` и установленный Chromium (`CHROMIUM_PATH`, по умолчанию `/usr/bin/chromium`). HTTP-ответы со статическим пакетом отдаёт сам тестовый runner; сервер и внешняя сеть не нужны. Это проверяет клиентскую маршрутизацию и вложенные адреса, но не заменяет проверку Vercel после публикации. Скриншоты и trace сохраняются в игнорируемые рабочие каталоги.

## Vercel — подготовка, без публикации

1. Импортировать репозиторий в Vercel после отдельного решения о публикации.
2. Root Directory: `frontend`; Framework: Vite; Node.js: 24.x.
3. Install: `npm ci`; Build: `npm run build`; Output: `dist`.
4. `vercel.json` задаёт SPA fallback для вложенных страниц. `/assets/` выдаётся как статические файлы.
5. Проверить Preview: прямой вход на `/stories`, перенаправление старого `/quiz/1`, перезагрузку вложенных URL, изображения, полный маршрут и сброс.
6. Только после приёмки выполнить production deployment.

Не нужны переменные окружения, база данных или серверные функции. Проверить настройки Vercel/Git-интеграции: не включать автоматический выпуск из основной ветки до согласования.

Перечень интерфейсных изменений — `INTERFACE_CHANGES.md`. Результаты проверки — `VERIFICATION.md`.

## Архитектура и совместимость

Текущая ветка разработки — `story-design-system`. Сценарии Лизы и Никиты подключены к общим компонентам. Живые диалоги показывают одну текущую реплику с переходами назад/вперёд, переписки — все сообщения одновременно, монологи отделены от диалогов.

Схема состояния — версия 5, старые версии 1–4 мигрируют без сброса прогресса. Подробности правил доступа, исключений старого пилота и будущего полного режима: [docs/story-selection.md](docs/story-selection.md).

На Windows используйте `npm.cmd ci` и `npm.cmd run dev`, если PowerShell блокирует `npm.ps1`. Откройте адрес Local, напечатанный Vite. С главной перейдите к выбору и начните Лизу; после её завершения станет доступен Никита.
